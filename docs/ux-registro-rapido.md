# Registro rápido de comprovantes

> **Distribuição pública:** participantes, e-mails, domínio Workspace, IDs de Drive/pastas e projeto Cloud são fictícios. Documentos de validação preservam registros do desenvolvimento operacional; seus números não são resultados desta cópia pública. A validação da distribuição está em `docs/distribuicao-publica.md`.


A etapa 05A implementa um fluxo exclusivamente sintético: Hoje → Registrar comprovante → fotografar/selecionar → revisar os dados → salvar e conferir a resposta do servidor. A missão vem da página e do padrão do usuário; participante vem da sessão; data e moeda são sugestões revisáveis.

Com JavaScript há prévia e preservação do arquivo em erro de validação; sem JavaScript há formulário HTML nativo e os textos são preservados, com aviso para selecionar novamente o arquivo. Os complementos e checklists variam por tipo. Rascunho permite completar depois.

Não se elimina requisito documental para reduzir cliques. Marcação de checklist não valida despesa. Participação na subvenção é independente da autorização. O nome técnico é gerado pelo sistema somente quando seus componentes obrigatórios existirem, incluindo processo autorizado.

A confirmação distingue metadados no SQLite, arquivo temporário recebido, falha/indisponibilidade e sincronização pendente. Não há confirmação de Drive ou segurança para fechar antes de armazenamento durável. O uso real continua proibido.

A etapa futura deverá conectar o Shared Drive, confirmar armazenamento remoto pela API e tratar tentativas, retenção, arquivo técnico e campos exigidos pelos documentos aplicáveis da FACEPE antes de liberar comprovantes reais. Não há OCR, orçamento ou envio simulado.

Detalhes de funcionamento, limites e segurança: [captura de comprovantes](captura-comprovantes.md).
